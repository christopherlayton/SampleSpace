# Sample Space — build plan

*A gamified macOS app for learning R and the statistics behind a dissertation.*
Working title: **Sample Space** (a statistics term, and the game's theme: you pilot a survey ship across a star map, and every system you chart is an R skill or a stats concept).

---

## 1. The game in one page

**Core loop:** open the Star Map → pick an unlocked planet → read a short briefing → do the challenge (real R code, run against real R) → earn XP and 1–3 stars → unlock the next planet. Concepts you've cleared come back later in the *Review Nebula* (spaced repetition) so they stick.

**Why it's visual:** the stats concepts are taught in *Labs* — native interactive simulations (sliders, draggable points, animated sampling) built with Swift Charts. You *feel* the Central Limit Theorem before you type `replicate()`. Every Lab ends with "now do it in R", so the intuition and the code are tied together.

### Level types
| Type | What you do | Example |
|---|---|---|
| **Briefing** | Read a short illustrated lesson, answer 1–2 check questions | "What is a factor?" |
| **Code** | Write R in the in-app editor; real R runs it; automatic checks pass/fail with friendly feedback | "Create `scores` and compute its mean" |
| **Predict** | Guess what code will output *before* running it | "What does `c(1, "a", TRUE)` become?" |
| **Debug** | Fix broken code | A `t.test()` call with the formula backwards |
| **SPSS Translate** | See an SPSS menu path / syntax / output table, write the R that produces the same result | Analyze → Compare Means → Independent-Samples T Test → `t.test(score ~ group, var.equal = TRUE)` |
| **Lab** | Interactive simulation of a stats concept, with a goal to hit | Drag n until the sampling distribution's SE < 2 |
| **Boss** | Multi-step realistic analysis: import, clean, check assumptions, test, plot, write the APA sentence | "Do the two teaching methods differ?" |

### Game systems
- **XP and ranks:** Cadet → Ensign → Lieutenant → Commander → Captain → Principal Investigator.
- **Stars per level:** ★ pass, ★★ no hints, ★★★ first try (or under "par" runs).
- **Fuel (streak):** daily practice keeps the ship fuelled; a missed day costs fuel, not progress.
- **Badges:** "First Plot", "Null Hypothesis Survivor", "Assumption Checker", "SPSS Defector", etc.
- **Review Nebula:** quick-fire cards (fill-in-the-code, concept MCQs, "which test?") scheduled by a simple spaced-repetition algorithm.

### Curriculum (sectors on the star map)
| # | Sector | R skills | Stats concepts |
|---|---|---|---|
| 0 | Launch Pad | console, arithmetic, objects, functions, help | — |
| 1 | Vector Belt | `c()`, indexing, types, `NA`, factors | levels of measurement → R types |
| 2 | Data Frame Docks | data frames, tibbles, `read_csv`, `haven::read_sav` (your SPSS files!), `str`, `summary` | variables vs. cases |
| 3 | Wrangler's Reach | `dplyr` verbs, `\|>`, recoding, missing data, reshaping | reverse-scoring, composite scales |
| 4 | Descriptive Drift | `mean/sd/var`, `psych::describe`, frequency tables | central tendency, spread, skew, kurtosis, z-scores |
| 5 | Plot Nebula | `ggplot2`: histogram, boxplot, scatter, bar + error bars, APA theme | reading distributions visually |
| 6 | Probability Expanse | `rnorm/pnorm/qnorm`, `sample`, `set.seed`, `replicate` | distributions, sampling distribution, CLT, standard error |
| 7 | Inference Station | — | hypothesis logic, p-values, CIs, Type I/II error, effect size, power |
| 8 | Means Cluster | `t.test`, `car::leveneTest`, `effectsize::cohens_d` | one-sample, independent, paired t; assumptions |
| 9 | Variance Rift | `aov`, `TukeyHSD`, `afex`/`rstatix` | one-way, factorial, repeated-measures ANOVA; η² |
| 10 | Relationship Ring | `cor.test`, `chisq.test`, `lm`, diagnostics | correlation, chi-square, simple & multiple regression |
| 11 | Dissertation Dock | Quarto, APA tables, project structure, `renv` | full reproducible analysis report |
| 12 | *(optional)* Python Wormhole | pandas, statsmodels, seaborn | the same analyses, side by side with R |

### Labs (native interactive simulations)
Distribution Sculptor (mean/SD sliders, shaded areas, z-scores) · Sampling Machine (CLT from a skewed population) · CI Rain (100 intervals, how many catch μ?) · p-value Courtroom (null distribution vs. your observed statistic) · Power Reactor (n × effect size × α) · Correlation Drag (drag points, watch r; outlier influence) · Least-Squares Fit (drag a line, see squared residuals) · ANOVA Splitter (between vs. within variance) · Chi-square Grid (observed vs. expected) · p-Hacking Garden (why multiple testing inflates Type I error).

## 2. Architecture

- **App:** SwiftUI, Swift 6, macOS 15+ target, `@Observable` state. Dark starfield look with `Canvas`/`TimelineView` animation; Swift Charts for Labs.
- **Project file:** generated by **XcodeGen** from `project.yml` (plain text, easy to edit in later sessions; no hand-editing `.pbxproj`).
- **Build:** Xcode-beta is the only Xcode on this Mac and isn't the selected toolchain, so every build uses:
  `DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer xcodebuild -project SampleSpace.xcodeproj -scheme SampleSpace build`
- **App Sandbox: off.** The app launches the system R (`/usr/local/bin/Rscript`, R 4.5.3 arm64 — native Apple silicon). Personal app, not for the App Store.
- **R engine:** a Swift `actor REngine` runs `Rscript runner.R job.json`. `runner.R` evaluates the learner's code in a fresh environment with a time limit, captures console output, errors and warnings, saves any plot to PNG, runs the level's checks, and writes a `result.json` that the app shows. (Later optimisation, only if it feels slow: a persistent R session.)
- **Content is data, not Swift code.** Each level is a folder:
  ```
  Content/sector-01-vectors/03-indexing/
    level.json     # id, title, type, xp, par, hints, unlocks
    lesson.md      # briefing text (Markdown)
    starter.R      # what the editor starts with
    solution.R     # reference answer (never shown unless you give up)
    check.R        # checks, e.g. expect_object("x", 5); expect_called("mean")
  ```
  This makes content sessions cheap: no Swift changes needed to add levels.
- **Content validator:** `scripts/validate_content.sh` runs every `solution.R` through its `check.R` and reports failures, so broken levels are caught before you play them.
- **Progress:** one JSON file in `~/Library/Application Support/SampleSpace/`.
- **Datasets:** bundled CSVs (`palmerpenguins`, plus small simulated education/psych datasets that mirror dissertation-style designs), and later your own `.sav` files.
- **Data bank:** real space datasets in `Content/data-bank/` (each with source, licence and the levels that use it in its README). First entry: the astronaut database (Stavnichuk & Corlett, 2020; CC BY 4.0), 1,277 missions by 564 astronauts. Good later uses: *t*-test of mission hours by military/civilian (Means Cluster), ANOVA of hours by decade (Variance Rift), chi-square of military status by nationality and regression of total hours on number of missions (Relationship Ring), always one row per person. Other candidates found: NASA Exoplanet Archive, Challenger O-ring data (Dalal et al., 1989), NASA meteorite landings, HYG stars (CC BY-SA), GCAT launches (CC BY).

## 3. Build steps (one Claude session each)

Each step is sized to fit one session and ends with something that builds and runs. **Start each session in this folder and say: "Do the next step in PLAN.md."** Tick the box and add a line to the Decisions log when a step is finished.

Size: **S** small · **M** medium · **L** large (may need a second session).

- [x] **Step 0 — Setup (you, ~10 min, no Claude needed).** Install the R packages and XcodeGen (commands in §4). Optionally install Positron or RStudio for your real dissertation work.
- [x] **Step 1 — App skeleton (M).** `git init`; `project.yml`; app shell with sidebar (Star Map / Review / Profile), starfield background, placeholder star map with a few planet nodes; builds and launches.
- [x] **Step 2 — R engine (M).** `runner.R` harness + check helpers; Swift `REngine` actor; handles errors, warnings, timeouts, infinite loops and plot capture; unit tests that run real R.
- [x] **Step 3 — Content format (S).** Level/sector models, loader, `validate_content.sh`, three sample levels in Sector 0.
- [x] **Step 4 — Code level screen (L).** Editor with R syntax highlighting, Run / Check / Hint / Reset buttons, console panel, plot panel, check results with friendly messages, star scoring. **Milestone: a playable vertical slice; you can start learning here.**
- [x] **Step 5 — Progress and game systems (M).** XP, ranks, stars, fuel/streak, badges, map unlocking, celebration animations, saved progress.
- [x] **Step 6 — Content: Sectors 0–2 (M, content only).** ~25 levels: R basics, vectors and types, data frames, importing CSV and `.sav`.
- [x] **Step 7 — Lab framework + first two Labs (L).** Lab container (goal, controls, "now do it in R" hand-off); Distribution Sculptor; Sampling Machine.
- [ ] **Step 8 — More level types (M).** Briefing quizzes, Predict, Debug, SPSS Translate (with SPSS output tables shown as images/tables).
- [ ] **Step 9 — Content: Sectors 3–5 (M, content only).** Wrangling with dplyr, descriptive statistics, ggplot2.
- [ ] **Step 10 — Labs, round 2 (L).** CI Rain, p-value Courtroom, Power Reactor, Correlation Drag, Least-Squares Fit.
- [ ] **Step 11 — Content: Sectors 6–8 (M, content only).** Probability and sampling, inference, t-tests. Sector 6 already holds the two Step 7 lab levels (folders 01–02); place the new code levels around them and renumber folders freely (ids live in level.json).
- [ ] **Step 12 — Review Nebula (M).** Spaced-repetition scheduler, quick-fire card types, daily review goal.
- [ ] **Step 13 — Content + Labs: Sectors 9–10 (L).** ANOVA, chi-square, correlation, regression; ANOVA Splitter, Chi-square Grid, p-Hacking Garden.
- [ ] **Step 14 — Boss levels + Sector 11 (L).** Multi-step analysis levels with APA write-up checks; Quarto report pipeline; "Dissertation Dry Run" finale (optionally on your own data).
- [ ] **Step 15 — Polish (M).** App icon, sounds, onboarding, settings (R path, font size), accessibility, performance pass.
- [ ] **Step 16 — *(optional)* Python Wormhole (L).** Python runner beside R; the same analyses in pandas/statsmodels.

**Usage tips:** content steps (6, 9, 11) are the cheapest and can be split at sector boundaries. If a session runs short, stop at a point where the app builds, note where you stopped under the step, and the next session continues from there.
